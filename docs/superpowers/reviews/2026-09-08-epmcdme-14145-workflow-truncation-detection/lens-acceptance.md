- The design requires `_last_finish_reason`/`_last_truncated` to be reset "at the start of each supervisor turn" in addition to the start of `invoke_task`, but `_detect_terminal_truncation` (src/codemie/agents/langgraph_agent.py:1250-1272) only ever sets the flags when it finds a truncation match — it has no branch that clears them back to `None`/`False` when a terminal message is not truncated. Because `parse_supervisor_message_type` is dispatched once per subagent author within a single `invoke_task` call (src/codemie/agents/langgraph_event_adapter.py `dispatch_supervisor_chunk`/`process_chunk_for_supervisor`), a truncated intermediate subagent answer can leave `_last_truncated=True` set even after a later, non-truncated final terminal message of the same call is processed, so the persisted `finish_reason`/`truncated` on the workflow state could misreport a complete final answer as truncated in multi-agent (supervisor) flows. No test in the diff drives two terminal messages (truncated-then-not-truncated) through the same agent instance to exercise this sequence.
