## Decisions

- **(a) Move set: all 20, no exception.** `_manageable_project_names` is called inside the IO function (`:319`) and cannot stay in the router without a signature change. `_can_see_project_spending` could stay in `crud.py` (sole caller `:326`, no IO), but it repeats the same admin / auditor / project-admin / personal disjunction as `_manageable_project_names`; splitting two copies of one rule across layers invites drift. 7b's reason to keep its gate (HTTP exception, `_common` constants) does not apply: neither predicate imports HTTP or `_common`. The inline checks at `spending.py:84-89` and `crud.py:259,320` stay.
- **(b) `_spend_repo` becomes public `spend_repo`, same single instance.** `spending.py:36,97` would otherwise import a private name from a service module; `spend_repo` appears nowhere in `src/` today (no collision). Rejected: switching `spending.py` to the existing singleton `project_spend_tracking_repository` (`repository/project_spend_tracking_repository.py:1098`): a redesign that changes which object the patches reach. The second instance stays (non-goal). It is still built at import of the module that owns it, which `crud.py` imports at app load. Patch rule: a dotted `spend_repo.<method>` patch reaches the one shared instance whatever module path names it; a whole-name patch binds per module and must name the module that reads the name at call time.
- **(c) Retarget rule: patch where the code under test resolves the name.** The moved functions read `get_async_session`, `budget_repository`, `project_budget_assignment_repository` and `spend_repo`, so all **35** `_spending_support.*` literals (`test_projects_router.py` 31, auditor file 4) go to `codemie.service.project.project_spending_service.*`; **0** stay on `crud`/`spending`. The **9** whole-name `spending._spend_repo` literals (`test_projects_router.py` 8, auditor 1) stay on `codemie.rest_api.routers.projects.spending`, renamed to `spending.spend_repo` (that handler reads it). The `crud.get_async_session` and `crud.project_budget_assignment_repository` literals serve `crud`'s own `_attach_assigned_budget_summaries` and are untouched. The 4 imports move to the service module with public names; 7 call sites rename (`is_budget_period_open` 4, `manageable_project_names` 1, `can_see_project_spending` 2). New paths are shorter than the old, so no line reflows.
- **(d) Public names** as the map above: the pure helpers are the unit-testable surface, and 7b also made all four of its functions public. Rejected: public only for the 6 names read from outside the module, which would push the characterization tests through private names or heavy IO mocking.
- **(e) Typed signatures from the start.** Nine signatures carry bare `list`/`dict` or untyped parameters at BASE: `aggregate_budget_window`, `build_widget_rows`, `key_row_to_widget`, `manageable_project_names`, `project_spending_summary`, `attach_project_spending_summaries`, `can_see_project_spending`, `populate_project_spending_summary`, `populate_project_spending_widget`. They gain the element types the bodies read (rows `ProjectSpendTracking`, `| None` where the body passes `None`; assigned budgets `ProjectAssignedBudgetSummaryRow`; `budgets_by_id`/`budgets_map` `dict[str, Budget]`; enriched projects and `project_detail` `dict[str, Any]`). All other annotations stay as at BASE. Annotations only: no body, default or parameter-name change.
- **(f) Tests.** Characterization tests go to new `tests/codemie/service/project/test_project_spending_service.py` (flat `test_<module>.py`, as that directory does). A second new file, `tests/codemie/rest_api/routers/test_projects_spending_wiring.py`, pins what no test pins today at handler level: a non-privileged member sending `include_spending=true`, and a list mixing manageable and other projects. `_WIDGET_COLUMNS` is pinned through the widget the populate function builds, not imported.

## Behavior that must not change

- **Access.** Both predicates are `user.is_admin` or `getattr(user, "is_auditor", False)` or project admin or `project_type == PERSONAL` (string or enum). `can_see_project_spending` returns a real `bool` (it wraps the project-admin flag in `bool()`); `manageable_project_names` keeps input order. `attach_project_spending_summaries` returns before opening a session when no project is manageable, leaving `item.spending` untouched; otherwise it queries only the manageable names and assigns `item.spending` for every item (`None` when it has no rows).
- **Reset text.** `None` gives `None`; a naive datetime is UTC; at or before now `"0 days"`; one day or more `"N day(s)"` (singular at 1); under a day `"N hour(s)"` (singular at 1, `"0 hours"` under an hour).
- **Period and parsing.** `is_budget_period_open` is false for no budget, `None` or empty reset; true only for a reset strictly later than now; naive is UTC; `Z` reads as `+00:00`.
- **Selection and aggregation.** Four category branches: assigned and same budget kept; assigned, other budget, period open kept; unassigned, open, spend above zero kept with `None`; the rest dropped. Window: assigned budgets sum `max_budget`; otherwise the budgets behind the rows, skipping `None` rows, falsy ids, missing and soft-deleted budgets; earliest known reset; `(None, None)` when nothing resolves. The latest row wins only on a strictly later `spend_date`.
- **Summaries and widget.** Money rounds to 2 decimals; percent is 0.0 without a limit; widget row ids `"Default"` (empty budget id) and `"Key"`; exactly the six `_WIDGET_COLUMNS` (ids, labels, types, formats, descriptions); key row appended last; no widget without rows; no summary with neither key nor budget rows.
- **Detail IO.** One session for all reads (the budget-rows read is conditional), then compute with the clock read after. Subject type is `project_budget`, else `budget` (with `rows_limit`), else `key` when only a key row exists; lifetime spend is read for that type. The category path filters through `select_category_rows`.
