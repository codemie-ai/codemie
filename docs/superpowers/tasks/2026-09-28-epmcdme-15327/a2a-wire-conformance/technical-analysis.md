### Patterns and Conventions
- Pydantic v2 models, camelCase field names written literally in Python (no alias generator) except `Task.id`/events/`TaskIdParams` (alias `taskId`). Persistence uses `model_dump()` WITHOUT `by_alias` (base.py `PydanticType.process_bind_param`): if new fields use aliases (`media_type` -> `mediaType`) the stored JSON would use Python names and diverge from wire; keep wire names as Python attribute names, or handle serialisers explicitly.
- Enum serialisation: `model_dump()` in python mode leaves `str`-Enum members in the dict; JSONB serialises them as their str value, so `TaskState.value = "TASK_STATE_*"` will be what is stored.
- Response serialisation: router dumps `model_dump(exclude_none=True, by_alias=True)`. `exclude_none` also strips legit nulls, and empty lists are kept (`artifacts: []`).
- /v1/a2a authentication (for FR-S7): route dependency is `security.authentication.authenticate` → `get_user_provider().authenticate_and_load_user(request, IdpFactory.create())`; also honours an internal HMAC path (`bind-key`/`X-Bind-*` headers, service-to-service only) and Teams-bot impersonation. Accepted credential is therefore deployment-dependent on `config.IDP_PROVIDER` (`local`, `keycloak`, `oidc`, `entraid-oidc`; default `local`):
  - `local` (base package, only registered IdP): header `user-id`, falling back to raw `Authorization` header value used as the user id (no scheme parsing; a JWT is *not* validated; in `ENV=local` a stub user, otherwise DB lookup).
  - enterprise IdPs (registered at startup via `IdpFactory.register`; not in this repo) — `jwks_validating.py` wrapper: `Authorization: Bearer <JWT>` required (rejects non-Bearer with 401; also a session cookie path for cookie-only flows).
  - So statically the honest description is an `http`/`bearer` scheme (`bearerFormat: JWT`) for keycloak/oidc/entraid, and `local` is not really bearer. FR-S7's fallback ("http bearer if it cannot be determined statically") is correct as the default; `local` deployments effectively need `user-id`, which can be advertised as an `apiKey` in header `user-id` only if `config.IDP_PROVIDER == "local"`. There is no API-key auth for this endpoint. The old `credentials="dev-codemie-user"` leak in `_get_agent_authentication` disappears when `authentication` is removed.

## 6. Risk Indicators

- **PydanticListType silently drops invalid items on read** (`base.py:337-353`, `except Exception: continue`) and returns `[]` for NULL. Any stricter validator (e.g. `Message.parts` non-empty, required `messageId`, unknown legacy state `unknown`) that raises on a stored legacy item will erase that history/artifact entry with no log. `PydanticType` (used for `status`, `agent_card`) has no such guard and raises. Normalisers must be total (FR-T1a warns and maps `unknown`→FAILED; also legacy `Artifact` with `index`, missing `messageId`, `file` parts).
- **SQLModel `table=True` models do not run pydantic validation/before-validators on `__init__`**; only nested sub-model deserialisation through `PydanticType.model_validate` does. So `Task`-level "`sessionId`→`contextId`" and "`taskId`→`id`" normalisation must not rely on a `Task` before-validator for DB reads (SQLAlchemy loads columns directly); the `sessionId` fallback is a column-level read (`task.contextId or task.sessionId`), as today at `codemie_task_manager.py:293/303`.
- **Persistence uses `model_dump()` (no by_alias/exclude)**: aliases and `exclude=True` diverge between wire and storage (also affects `AgentCard` internal-field exclusion — `Field(exclude=True)` would strip `user_id/project_name/integration_id/bedrock_agentcore` from the stored assistant card and the version-compare dump). Same trap for `Task.assistant_id/user_id` which are already `exclude=True` fields on the table model (works only because they are real columns, not JSON).
- `Task.id` alias `taskId` is shared by `TaskIdParams`, events and the JSON `Task` — a single-place change, but every test and the client's request bodies key off it; FR-T5 flips serialisation to `id`.
- **Client swallows JSON-RPC error bodies on HTTP 4xx**: `_send_request` raises `A2AClientHTTPError` on `raise_for_status()`, and CodeMie's own pre-dispatch errors are HTTP 400 (FR-S6); FR-C3 (`-32601/-32600/-32009` → `A2AClientProtocolVersionError`) will never trigger for such remotes unless the client inspects 4xx bodies; streaming path (`aconnect_sse`) has no status check for non-200 either. Handler also has no `A2AClientError` mapping (would be 500).
- **Streaming close logic depends on `final`** in `assistant_handlers.py:1440` and `remote_agent_connection.py:72`; removing `final` (FR-T8) requires terminal-state detection in both, and `{message}` StreamResponse/SendMessageResponse must complete the stream and feed `convert_to_base_model_response`, which currently assumes a Task (`artifacts[0]`, `status.message.parts[0].text`, no guard for empty).
- **Router 422 pre-emption**: `A2ARequestBody` (`id: str`, `method: str`, `params: Dict`) makes FastAPI reject non-JSON/wrong-typed bodies (422) before FR-S6's `-32700/-32600/-32602` logic, and the FR-S1 "gate before body validation" ordering; swapping to raw `await request.json()` changes Swagger (FR-S8 keeps a body model for docs only). `execute_a2a_request` also returns HTTP 200 for the task-level errors but `_handle_exception` uses 400.
- Card served via `response_model=AgentCard` on two routes (well-known GET and `/assistants/fetch`): FR-T10 public exclusion must apply to the well-known route and `GetExtendedAgentCard` but `/assistants/fetch` must continue returning internal fields (the UI stores that card into the assistant create request, `models/assistant.py:361`, then `routers/assistant.py:774` reads `bedrock_agentcore`).
- Card model change is a persisted-schema change with no migration: stored `Assistant.agent_card` JSON (legacy `transport`, `authentication`, `stateTransitionHistory`, `defaultInputModes:["text"]`, skills lacking `tags`/`description`, `protocolVersion` absent) must load through before-validators on every `PydanticType(AgentCard)` read (assistants table, version table); `AgentSkill.tags/description` become required in FR-T10 — legacy remote cards frequently omit them, so they need defaults on input; `AgentCard.description` is required while `assistants.description` may be None (`assistant_to_agent_card` passes `assistant.description`).
- Spec ambiguity for the implementer: proto `AgentCard` includes `protocolVersion` only on interfaces; current before-validator handles only top-level `url` (not `additionalInterfaces` without `url`, and not interfaces already in `supportedInterfaces` using `transport`). FR-T11 extends this to per-interface `transport`.
- `invoke_with_a2a_output` returns `require_user_input=True` on *any* agent exception (assistant_agent.py:404-414), so real failures present as `TASK_STATE_INPUT_REQUIRED` with the error text; only exceptions escaping (MCP auth) reach FAILED. TR-7 "failed agent" flows must be built accordingly.
- Speculative: `SendStreamingMessage` leading `{task}` frame needs the persisted Task snapshot to be built before the agent is set up; `update_store` ordering (WORKING is written before `_setup_agent` in streaming but after in sync) will need to be unified so a failure in `_setup_agent` still yields a terminal status frame.
- Speculative: Task-id generation moves server-side (spec FR-S2); `upsert_task` and `_check_existing_task` currently key on `params.id`, and the client sends `raw_request.state.uuid` as the task id today — the new client should not send a `taskId` for a fresh task, but a follow-up conversation reuse of `contextId`/`taskId` from `conversation_id` needs a design decision (currently `sessionId=chat_request.conversation_id`).
- Speculative: `A2A-Version` query fallback and `-32009` gate must also apply to the SSE route; error-before-stream must not be returned as `StreamingResponse`.
- Documentation drift: the guide and `version.py` claim things not yet true; both need correction (FR-D1). Prior slice analyses contain stale details; trust source.

## 7. Summary for Complexity Assessment

The change re-shapes the whole in-house A2A stack: one 463-line protocol module (`a2a/types.py`, ~every model changes: enums, Message/Part/Artifact/Task/events/requests/responses/AgentCard, new error data, new StreamResponse/SendMessageResponse unions, new client error), the router (`routers/a2a.py`: version gate, `-32601`/`-32602`/`-32700` handling, typed error data, Swagger body), the server task manager (task/context-id generation, `configuration` handling, streaming order with a leading `{task}`, no `final`, history semantics, new states), the client trio (`client.py`, `remote_agent_connection.py`, `card_resolver.py`) plus `utils.py` converters and the chat-facing `A2AAssistantHandler`, and two docs (guide, `version.py`). The type consumers are confined to the a2a package, one router, one handler, `models/assistant.py` (stores `AgentCard` in two tables) and `alembic/env.py`; no UI-facing schema or agent/tool code imports A2A types (only `BaseModelResponse.task_id: str`). Roughly 10 source files and ~10 test files (about 3,450 lines of existing tests, most of which assert the old shapes and must be rewritten) plus a new fixtures directory.

Technical novelty is moderate: no new dependency and no migration, but the wire contract is being matched to an external proto (ProtoJSON enums, oneof envelopes, `google.rpc` error details) and every shape must additionally be readable from legacy data. The riskiest area is persistence: JSONB columns are deserialised through `PydanticType`/`PydanticListType` using plain `model_dump()` (no aliases/excludes), `PydanticListType` silently drops list items that fail validation, and SQLModel table models skip validators, so legacy-normalisation has to live in nested sub-model before-validators and be exception-free. The stored assistant `agent_card` shares the `AgentCard` model with the served card, so hiding internal fields cannot use `Field(exclude=True)`.

Test posture: good unit coverage of the current behaviour with heavy mocking (DB methods patched, no DB round-trip, no fixtures, no gate/`-32601`/error-data/`message`-result/`A2AProtocolVersionError` tests). Key risk factors: (1) client cannot currently see JSON-RPC error bodies on HTTP 4xx, so FR-C3 needs client transport changes beyond types; (2) streaming termination in both client and chat handler depends on the removed `final`; (3) FastAPI's `A2ARequestBody` validation pre-empts the JSON-RPC error semantics required by FR-S6/FR-S1; (4) the auth advertised in `securitySchemes` is deployment-dependent (`IDP_PROVIDER`), with `http bearer` as the correct static default; (5) `invoke_with_a2a_output` maps agent errors to INPUT_REQUIRED. Alembic head is `c9d8e7f6a5b4` (down `u2v3w4x5y6a7`), unchanged and untested on a real DB.
