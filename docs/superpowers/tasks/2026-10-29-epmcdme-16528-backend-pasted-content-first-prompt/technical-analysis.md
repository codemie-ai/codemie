### (d) Title precedence: where `session_title` is reachable
- Hook events are decoded in `postgres/otlp.py:_hook_event_row` (`:900-925`): keys in `HOOK_KNOWN_KEYS` (`vocabulary.py:124`) become typed columns; everything else -> `hook_events.attrs jsonb` via `_jsonb(extras)` (`otlp.py:447`). So `session_title` and the CLI's `prompt_original` sit in `hook_events.attrs` of `agent.session.start` and `agent.prompt.submit` rows. `hook_events` is partitioned by week on `ts`, indexes `(session_id, ts)` and BRIN `ts` only; **no index or GIN on `attrs`**. Per-session lookups by `(session_id)` are index-bounded. Raw retention 90 days drops the partitions (and `prompt_original`).
- attrs are queried per session elsewhere: `_attr_candidate` (`rollups.py:842-852`, latest non-empty string key of `agent.session.start`/`agent.git.snapshot` ordered by ts DESC LIMIT 1) and `_LATEST_VALUES/_LATEST_FIELD` (`:858-896`, latest non-empty value per key from hook + usage attrs). `_LATEST_FIELD` accepts common keys `_COMMON_TEXT` (`:783`) from any event, and env/git/summary keys only from their events. **`session_title` is not in any of these lists, so it never reaches `session_dims`**; `session_dims.attrs` only takes keys of summary/env/git events (`_ATTRS_EVENTS :795`). `prompt_original` likewise never reaches `session_dims`.
- Adding a column: `session_dims` is a plain (unpartitioned) table, PK `session_id`, `fillfactor=90` (`a1c1a0000001:~255-268`); the `title` column already exists. New nullable `text` column = metadata-only `ALTER TABLE ... ADD COLUMN` (style: `_add_columns` helper in `a1c1a0000006`, `_SESSION_DIMS_B`). `migrations.py` runs `alembic upgrade head` at pod start under an advisory lock, `lock_timeout 2min`. **Test coupling**: `tests/.../postgres/test_migrations.py:187-245` `_declared_columns()` reads only `INITIAL_SCHEMA.UPGRADE + SCHEMA_EXTENSION.UPGRADE`; `test_every_column_the_recompute_writes_is_declared_by_the_revisions` fails if the recompute `INSERT INTO session_dims (...)` writes a column that only a third revision declares, unless the helper is extended. `_SESSION_DIMS_COLUMNS` (`rollups.py:802-810`) must also list any new column (it feeds `_NOT_ATTRS`).
- Existing merge kinds for a new column (storage guide `cli-analytics-storage.md:144-153`): "latest value" (env/git/common fields: latest non-empty by ts) fits a `/rename`: latest wins. The title **column** `title` is "summary" kind (written only when the summary's `ts >= summary_ts`, `_SUMMARY_WINS :971`). Whether Claude re-sends the updated name on each `UserPromptSubmit` is unverified (no capture in either repo), so "earliest vs latest" on `/rename` is a spec decision; latest-wins is the existing convention for mutable session context.
- Alternative with no schema change: compute precedence at read time in `get_session_detail_meta` / `_sessions` CTE with a correlated subselect on `hook_events.attrs->>'session_title'` (precedent: `reader.py:443` `ELSE (SELECT max(h.ts) FROM hook_events h ...)`), but the list query runs over a window of sessions, so this costs one index probe per session and the value disappears with raw retention. Rollup-time derivation persists it.

### (f) Regex / helper
Verified on the disposable PG 17.11 (container `pg-16528`, port 55432 only):
- Postgres ARE regex `'</?pasted_content(\s[^>]*)?(>|$)'` with flags `'g'`: whole-prompt, typed+paste, two blocks, mid-prompt, orphan closing tag, id with spaces/quotes all strip tags and keep text and inner newlines byte-for-byte. `(>|$)` also strips a tag truncated mid-attribute by the old CLI's 200-char cut (`Hi <pasted_content id="a` -> `Hi `). `<pasted_content_other>` and `<pasted_content>` (no attrs) behave correctly (the former is left alone, the latter stripped). A cut inside the tag name (`<pasted_con`) or `</pasted_cont` is not matched; no simple regex can tell it from user text.
- `btrim(x, E' \t\r\n')` after the strip yields a readable title (pasted-only -> `Step 1: log in\nStep 2: ...`).
- Cost: 200k paste-bearing prompts ~0.94 s (~5 us each), 200k plain ones ~0.11 s vs 0.03 s baseline; no ReDoS shape (no nested quantifier; `[^>]*` bounded by `>`). Applied once to the winning value `(array_agg(...))[1]` it runs once per recomputed session; applied inside `_PROMPT_OK` (per qualifying prompt row) still negligible.
- Helpers: `vocabulary.py` is pure constants + `humanize_harness_name` (`:156`), imported by the handler (`handler :38`), so a pure Python `strip_pasted_content()` fits there (or a new pure module under `repository/cli_analytics/`). `test_layering.py` only forbids `repository/cli_analytics` importing `codemie.service`; service -> repository is allowed. SQL building uses `_literal`, `_text_array` (`rollups.py:150,154`) and constants from `vocabulary`; the regex would be a literal built with `_literal`. A Python helper is directly unit-testable and can be shared with a SQL expression only by keeping the two patterns in sync (a parity test against live PG is the mitigation, `test_live_*` style).

## 6. Risk Indicators

- Existing rows: backfill reaches only the last 90 days (`mark_dirty` clamp, `rollups.py:2317-2320`) and cannot fix rows whose earliest raw rows were purged (`_earliest_merged` keeps the stored value). Older rows keep markup unless a one-off `UPDATE session_dims` or read-time normalisation is added. Speculative: read-time Python cleaning in the handler is the only option that covers all rows without a migration.
- `coalesce` + `''` trap in `_earliest_merged`: a cleaned value that becomes `''` (e.g. `<pasted_content id="a">` alone, empty paste) would overwrite a good stored prompt; needs `nullif(...,'')`. Whether a prompt that cleans to empty should be skipped (like `btrim(...) <> ''` in `_PROMPT_OK`) and the next prompt chosen is a design choice.
- Order of sentinel vs cleaning: `_PROMPT_OK` tests the raw body (`starts_with(h.prompt_body, ...)`); a paste block wrapping a sentinel (`<pasted_content ...>\n/clear...`) is unspecified. Speculative: apply sentinels to the cleaned text.
- Truncated tags from old CLIs (200-char cut): `(>|$)` handles a cut inside the attribute list; a cut inside the tag name is not recoverable. Leading newlines after stripping need a newline-aware trim (`btrim` default trims spaces only).
- Title precedence is undefined by any contract: `session_title` is only an unindexed key in `hook_events.attrs` (dies with raw retention), whether Claude resends it after `/rename` is unverified (no capture in either repo), `session_dims.title` is the transcript `ai-title` (different thing, currently not served), and `first_prompt` is the only served title. Three sources, no existing precedence rule.
