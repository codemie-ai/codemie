## Planning confirmations (spec-flagged items, verified on the branch)
- **Readers / purge tolerate binding-only rows.** `reader.py:81` and `:288` filter on `summary_ts IS NOT NULL` / `started_at IS NOT NULL`; `:446` and `:730` join `session_dims` (left join at 730). `session_purge.py:116-128` selects idle rows with `FOR UPDATE SKIP LOCKED`, so a row held by an ingest upsert is skipped. Task 6 adds a regression test; no reader change expected.
- **`backfill.reclassify` replay.** `backfill.py:74-89` only updates raw `event_kind` of kind-0 span/log rows. It never touches `session_dims` or hook project/binding columns, so the new columns are unaffected. The real hazard is the later rollup rebuild (`rollups.py:1905-1925`), covered in Task 5. Add a test that runs `reclassify` plus a recompute over a bound session.
- **Advisory lock cost.** `ingestor.py:177-178,477-487` already takes `pg_advisory_xact_lock` (sorted keys) for fork, lines and lines-metric sessions only. Task 5 widens the set to every session in the batch: one extra O(1) lock call per distinct session per request, held until commit, plus one indexed `session_dims` PK lookup. No new round trips beyond that. Note it in the cli-analytics-events doc.
