# Deferred from code review — 2026-10-07-cache-read-cost-per-model (2026-10-07)

- **Resolved model with no cache-read rate silently prices at zero** — `src/codemie/service/analytics/handlers/coding_agent_pricing.py:88-91` — `cache_read_cost()` returns 0.0 when `cost_config.cache_read_input_token_cost is None`, but `_price_cache_reads`'s unpriced check only tests `lookup_cost_config(model) is None`, so a resolved model with no cache-read rate contributes 0.0 without appearing in `unpriced`. Pre-existing: the same mismatched check already shipped in `_price_cache_reads`/`cache_read_cost` (used unchanged by `get_overview`/`get_cost` since before this change); this change only reuses the existing helper at more call sites, it does not introduce the gap.
- **No shared read snapshot between get_sessions' cost-facts and per-model cost queries** — `src/codemie/service/analytics/handlers/cli_analytics_handler.py:565-601` — `get_session_cost_facts` and `get_session_model_costs` run on separate pooled connections inside the same `asyncio.gather`, so a concurrent `cost_daily` write between them could make `cache_read_tokens`/`cost_usd` disagree with the new per-model `crc`/`model_name`. Pre-existing: `get_sessions` (and `get_overview`/`get_cost`) already gather multiple independent queries this way with no transactional snapshot; this change adds one more query to an already-non-atomic read pattern.
- **No shared read snapshot between get_session_detail's cost and per-model cost queries** — `src/codemie/service/analytics/handlers/cli_analytics_handler.py:671-695` — same non-atomic `asyncio.gather` pattern as above, applied to `get_session_detail_cost` vs. `get_session_detail_model_costs`. Pre-existing: `get_session_detail` already gathers seven independent queries (meta/cost/scalars/tools/events/dispatches/skills) with no snapshot isolation before this change added the eighth.
